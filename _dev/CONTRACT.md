## Что вы пишете

    reference: () => ({ … }),                  // эталонный ответ (тот же формат, что ans)
    render(el, ctx) { … },                     // рисует по ctx.ans; меняет ctx.ans и вызывает ctx.save()
    check(ans, ctx) { return { ok, score, summary, notes: [{ ok: true|false|'warn', html }], mentor }; },

## Как движок работает с заданием (js/app.js, mountTask)
- Задания с id `how-*` (или `theory: true`) — **теория**: блок «1. Теория», кнопка «Готово, дальше», в зачёт не идут.
  `covers: ['taskId']` ставит теорию перед заданием, которое она объясняет.
- Остальные — **практика**: блок «2. Практика», открываются по очереди. Кнопки: «Проверить», «Эталон (−3)» после
  первой проверки, «Сбросить ответ». Режим преподавателя открывает всё.
- `render(el, ctx)` вызывается заново после каждой проверки. `ctx.ans` — ответ (мутируйте и вызывайте `ctx.save()`),
  `ctx.result` — результат последней проверки (можно подсветить элементы), `ctx.readonly` — показ эталона: никаких
  активных полей, только просмотр. До проверки правильные ответы не подсвечивать.
- `check(ans)` — **чистая функция от ans**, без побочных эффектов, может вернуть Promise (нужно для SQL).
  `blank()` → `ok:false`; `reference()` → `ok:true, score:1`. Порог зачёта обычно `score ≥ 0.8` и все критичные пункты.
  `notes` — построчная обратная связь: что верно, что нет и **почему** (не «неверно», а объяснение). `mentor` — реплика
  Веры при типичной ошибке. Очки (доверие, опыт) начисляет движок — сами `TR.score` в check не вызывайте.
- `explain` — разбор: почему правильно именно так, частые ошибки, связь с реальной работой, источники.
- `ctx.decide(label, value)` — записать решение студента в отчёт преподавателю. `ctx.facts.unlock(id,'ask')` — только
  в m1-sdlc, m2-business, m3-cjm.

## Общие виджеты (js/ui.js, ui-diagram.js, ui-bpmn.js, db.js)
- Тексты: `ui.brief`, `ui.simple`, `ui.note(kind,title,html)`, `ui.say(who,html)`, `ui.table(cols,rows)`, `ui.status`,
  `ui.meter(ratio)`, `ui.code(src, lang, cap)` (lang: sql, json, http, text, js), `ui.http({method,path,headers,body}|{status,…})`.
- Интерактив: `ui.quiz(el,{q,options:[{t,ok,why}],multi,value,readonly,reveal,onChange})` + `ui.quizScore(cfg,value)`;
  `ui.sort(el,{items,buckets,value,reveal,readonly,onChange,seed})` — раскладка по корзинам;
  `ui.order(el,{items,value,reveal,readonly,onChange,seed})` + `ui.orderScore(value, correct)`;
  `ui.match(el,{rows,choices:[{v,t}],value,reveal,readonly,onChange})`; `ui.seg/ui.onSeg`; `ui.tabs`; `ui.modal`; `ui.toast`;
  `ui.justify(el,{q,rubric:[…5],reference,value,readonly,onChange,minLen})` + `ui.justifyScore(v)` — ответ своими словами:
  самопроверка по рубрике или проверка Claude (если доступен). Сигнатуры смотрите в коде.
- Диаграммы: `ui.seq(el,{lanes,steps,…})` — sequence с проигрыванием; `ui.er(el,{entities,rels,draggable,…})` — ERD
  с «вороньими лапками»; `ui.bpmn(el, cfg)` — BPMN (пулы, дорожки, события, задачи, шлюзы, граничные события, потоки
  сообщений; описание cfg — в шапке js/ui-bpmn.js); `ui.bpmnGlyph(type,label)` — один элемент для легенды.
- Данные: `TR.db` (sql.js, SQLite): `await TR.db.run(sql)` → `{ok,columns,rows,total,error,ms}` в общей песочнице;
  `await TR.db.compare(sql, refSql, {ordered})` → `{ok, mine, ref, why}` на свежих копиях; `TR.db.resultHTML(res)`,
  `TR.db.schemaHTML([tables])`, `TR.db.SCHEMA`, `TR.db.ENUMS`, `TR.db.ddl()`. Загрузка с CDN асинхронная — показывайте
  «Загружаю базу…» и обрабатывайте ошибку (нет сети) понятным сообщением.
- Утилиты: `TR.esc`, `TR.$/$$`, `TR.el(html)`, `TR.on(root,type,sel,fn)`, `TR.clone`, `TR.norm` (нижний регистр, ё→е,
  без знаков), `TR.shuffle(arr, seed)` (детерминированно), `TR.plural`, `TR.PEOPLE`, `TR.FACTS`, `TR.icon(key)`.

## Планка качества (обязательно)
1. **3 раздела теории** `how-*` и **5 практических заданий** (минимум 4). Теория — не стена текста: интерактив
   (переключатели «до/после», пошаговые демонстрации, «нажмите на элемент — узнаете, что это»), пример из «Искры»
   и соседний бытовой пример, типичные ошибки, как об этом спрашивают на собеседовании. Теория должна учить с нуля:
   студент мог не смотреть урок.
2. Практика — **разные механики** (не 5 квизов подряд): раскладка, порядок, сопоставление, конструктор диаграммы,
   редактор с живой проверкой по признакам, симулятор/лаборатория «решение → последствие», разбор чужого артефакта
   «найдите ошибки», ответ своими словами (`ui.justify`). Хотя бы одно задание — **лаборатория с последствиями**
   (как «Лера проверяет сборку» в Колосе), последнее — обычно объяснить заказчику или команде своими словами.
3. Всё — на кейсе «Искры» и по CASE.md: правила BR-*, статусы, люди, числа. Реплики персонажей — живые, в характере.
4. Проверки — щедрые к формулировкам и строгие к смыслу. Текстовые поля проверяйте по признакам/ключевым словам с
   `TR.norm`, показывайте признаки вживую, пока студент пишет. Каждая ошибка — с объяснением.
5. Язык — русский, простой, на «вы», без нерасшифрованных сокращений (при первом упоминании — расшифровка),
   «ёлочки», тире «—». Профессионально точно: ссылки на источники в разборах (Вигерс «Разработка требований»,
   Кокберн «Современные методы описания функциональных требований», BABOK, ISO/IEC 25010, BPMN 2.0 (OMG),
   UML 2.5, ГОСТ 34, Скрам-гайд, Кон «Пользовательские истории», Паттон, Дейт и т. п. — по теме).
6. Вёрстка: только токены темы (`var(--accent)`, `--surface`, `--text-2`, `--ok/--bad/--warn` и т. д.), никаких жёстких
   цветов — должно читаться в тёмной и светлой теме. Сетки — `minmax(0,1fr)`, `min-width:0`; широкие диаграммы —
   в контейнере с `overflow-x:auto`. Ширина телефона 360–390 px — без горизонтальной прокрутки страницы.
   Кнопки — `class="btn"`, `btn sm`, `btn primary`, `chip`; карточки — `card`; стеки — `stack`, `row`.
7. Объём: ориентир 70–140 КБ на файл. Никаких внешних библиотек и сетевых запросов (кроме TR.db).
8. Доступность: кнопки — `<button type="button">`, у полей — `aria-label`, состояния — `aria-pressed`.

  откройте PNG инструментом Read и посмотрите глазами: ничего не налезает, диаграммы читаются, в светлой теме контрастно.
- `bash _dev/sql.sh "SELECT …"` — выполнить SQL в базе «Искры» (для заданий по данным).
